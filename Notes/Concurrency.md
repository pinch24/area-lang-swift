Swift Concurrency는 동시성 문제를 런타임이 아니라 컴파일 타임에 처리한다는 것이 설계 원칙이다.
데이터 레이스, 콜백 지옥, 제어 흐름 상실, 스레드 폭발과 같은 문제를 해결하는 것이 목표다.
그 결과 "동시성 코드는 스레드가 아니라 데이터 소유권의 문제다"라는 진단으로 데이터의 접근을 제한하는 것으로 스레드 동시성 처리에 안정성을 증명한다.

# Swift Concurrency의 네 가지 철학적 기둥
## 1. Safety by default
   안전이 기본값, 위험은 명시적으로
   - Swift는 옵셔널로 null 크래시 제거, ARC로 메모리 오류를 제거한다.
   - 동시성에서는 타입 시스템으로 데이터 레이스 위험을 배제한다.
     위험을 감수하려면 nonisolated(unsafe), @unchecked Sendable 지정
   
## 2. Structured Concurrency
   동시성도 스코프를 가진다.
   동시성 작업도 코드 블록 안에 있어야 한다.
   이로써 얻는 효과
   - 취소 전파
     부모가 취소되면 자식도 모두 취소
   - 에러 전파
     자식 하나가 던지면 형제들 모두 취소 후 부모로 전파
   - 우선순위 상속
     높은 우선순위 태스크가 기다리는 자식은 자동으로 승격
   - 누수 불가
     스코프를 벗어나 살아있는 작업 없음을 보장
Task { ... }는 이 트리 밖으로 나가는 예외이므로 Swift는 필요할 때만 쓰는 것으로 취급한다.

## 3. Isolation
   스레드가 아니라 격리 도메인으로 사고한다.
   Swift에서 동시성 코드는 "이 코드가 어떤 스레드에서 동작하는가"를 묻지않고 "이 데이터는 어느 격리 도메인에 속하는가"를 묻는다.
   - actor
     상태를 소유하는 격리 도메인이다.
     안에서는 동기적으로 자유롭게 접근, 밖에서는 await로만 접근 가능하다. actor 경계는 await 없이 넘을 수 없다.
   - @MainActor
     UI 상태를 소유하는 글로벌 도메인이다.
   - nonisolated
     어느 도메인에도 속하지 않음을 의미한다.
     공유, 가변 상태를 가질 수 없다.
   
## 4. Sendable
   경계를 넘는 것은 증명되어야 한다.
   격리 도메인 사이를 오가는 값은 "옮겨도 안전함"을 보증해야함으로 Sendable 타입으로 지정된다.
   - 값 타입(struct/enum) 이다.
     복사되므로 안전하다.
   - actor는 자기 상태를 격리하므로 안전하다.
   - 클래스는 불변(final, let)만 가능하다.
   - 가변 클래스는 안전하지 않아서 컴파일러가 거부한다.

Sendable은 타입 기준이라 엄격하지만 non-sendable이라도 전달 후 사용되지 않는 것이 흐름 분석으로 증명되면 허용한다.
Swift Concurrency는 증명 가능하면 허용, 아니면 거부한다.

# 동시성 런타임 모델의 원칙: 협력적 스레드 폴
- 최대 스레드 수를 코어 수를 초과하지 않게해서 스레드 폭발을 차단한다.
- 스레드 중단(suspension)만 허용하고 블로킹은 금지한다.
  await는 스레드를 반납하고 나중에 이어서 실행한다. 그래서 '스레드에 묶인 상태(thread-local, 재귀 락)'을 가정하면 안 된다.
- Forward progress를 보장한다.
  태스크는 항상 진전을 만들어야 한다.
  세마포어로 await를 기다리는 코드는 이 계약을 깨고 데드락을 만든다.
- 취소는 협력적으로 처리한다.
  런타임이 강제로 죽이지 않고 취소 플래그만 세운다.
  정리 코드가 중간에 끊기지 않도록 하기 위한 선택이다.

await는 "여기서 스레드가 전환 될 수 있다" 표시이기도 하다.
액터 재진입(reentrancy, await 전후로 액터 상태가 달라질 수 있음)은 버그가 아니라 데드락을 피하기 위한 의도된 설계이고, 그래서 await가 문법에 노출된다.

# 철학의 진화
Swift 6.0 -> 6.2 -> 6.4
## Swift 6.0
위 원칙을 전부에러로 강제해서 기존 코드에서 수 백 개의 Sendable을 마주하게 되었다.

## Swift 6.2
"동시성은 기본이 아니라 선택(opt-in) 이어야 한다"는 원칙이 추가됐다.
순차 코드가 기본이고, 병렬은 개발자가 의도를 적을 때만 사용된다.

## Swift 6.4
동시성 구현에 마찰을 제거하는 단계이다.
원칙을 지키되 표현 비용을 줄이는 방향으로 변경하고 있다.
- weak let
- async defer
- withTaskCancellationShield
- ~Sendable
